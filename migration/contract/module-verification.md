Generated by `migration/bin/module-summary.php` from the two sweeps' state files.

§8 flips the proxy one module at a time, so this is the granularity the decision is
actually made at. **`reach%` is the column to read first**: a module can show a high
`ok%` because it was exercised and works, or because this tenant has no rows for it
and the sweep never got past the first page. Only the first kind is evidence.

`routes` counts every route resolving to that module's controllers, including POST-only
and placeholder routes the smoke sweep deliberately does not visit, so `reach%` is a
floor rather than a coverage figure.
